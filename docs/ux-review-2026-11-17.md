## How I ran it, and what I could not do through the real UI

- **Folder grant.** A real folder grant needs a user gesture that CDP cannot give. For the "add a folder" step only, I built a music folder in OPFS (the browser's private file system) and attached it through the page's `?harness=1` seam (`__nakliampHarness.adoptFolder`), as `test/library-e2e.html` does. I then reloaded the plain URL without the seam, and every later step used the real UI. The folder held 7 tagged 40-second MP3s in two albums (made with ffmpeg, with cover art) plus the 19 untagged files from `test/fixtures` in an "Odd Formats" folder.
- **Native drop-down lists.** CDP cannot drive the operating system's pop-up for a `<select>`. For the Tools menu, the Browse "View" list and the smart-playlist field list, I set the value in the page and fired its `change` event. Everything else was a trusted click or key press.
- **Browser zoom.** Chrome's default zoom on this profile is 90%. I sized the desktop viewport so the page saw exactly 1280x800 CSS pixels, and used device emulation for 360x740.
- **A second session on the same origin.** Halfway through, another agent session started `scripts/cdp-harness.py` test runs against `127.0.0.1:8878`. Those runs clear NakliAmp storage and `test/library-e2e.html` deletes every OPFS entry, so my test folder vanished under me. I moved to a private origin (`127.0.0.1:18923`, my own `python3 -m http.server`, now stopped) and repeated the affected steps. One finding below (minor 9) is real but was triggered by that wipe.
- **Indexing speed.** 26 files indexed in 0.1 s, so I could not watch progress. What the progress text says comes from reading `index.html:2479-2488`, not from observation.
- **Cleanup.** I closed every tab I opened, cleared the device and colour-scheme emulation, deleted my OPFS folder, NakliAmp's localStorage keys, IndexedDB database, service worker and `nakliamp-shell-v1` cache on the private origin, and stopped my server.

## Blocker

### B1. The full-window visualiser opens below the screen

- **Journey:** find the visualiser and Milkdrop.
- **Expected:** the ⤢ button (or Shift+V) fills the window with the visualiser.
- **What happened:** the visualiser panel starts at the top edge of the player bar and runs down past the bottom of the window. Only a strip about 110 px tall is visible, with "Exit" over it. The rest of the page stays on screen above it. With the button, the page also scrolled by 182 px. This is the only big view of the visualiser in the app, so a user who presses ⤢ sees a broken strip. This matches the owner's "I don't see the visualiser".
- **Cause (observed in computed styles):** `.playerbar` has `backdrop-filter: blur(18px)`. A backdrop filter makes the element the containing block for `position: fixed` children, so `.vis-wrap.full { position: fixed; inset: 0 }` (`index.html:150`) is pinned to the player bar, not to the window. The `.vis-wrap` measured `top: 636px, height: 800px` in an 800 px window.
- **Screenshots:** `17-visualiser-full.png` (Bars), `19-milkdrop-full.png` (Milkdrop).
- **Fix:** move the canvas out of the player bar when it goes full window (for example into a `<dialog>` opened with `showModal()`, or append `.vis-wrap` to `document.body` while full), or drop the backdrop filter from `.playerbar` while `.full` is on. Add a gate that checks the full-window canvas rectangle equals the viewport.

## Major

### M1. The visualiser is a 148x38 px strip, absent from Now playing, mobile and the mini player

- **Journey:** play an album, then look for the visualiser.
- **Expected:** a player that ships 30 visualisers and Milkdrop shows one somewhere you look while music plays.
- **What happened:** the only visualiser is a 148x38 CSS px canvas in the bottom-left corner of the player bar (`10-after-play.png`). The Now playing view, the largest surface in the app, shows a static cover square and no visualiser (`11-now-playing.png`). At 360 px wide the strip is hidden and only a ▦ picker button remains (`40-mobile-library-light.png`). The mini player hides it too but still shows the ▦ button (`35-mini-player.png`). The picker itself (`47-vis-picker-light.png`) is the best-looking screen in the app, yet it sits behind an unlabelled ▦ icon.
- **Fix:** put the visualiser in the Now playing view, behind or beside the cover, with a one-click switch between "Cover" and "Visualiser". Show it on mobile in Now playing. Label the picker button "Visualisers" in the full player.

### M2. Developer diagnostics are the main content of the player ("very M0 feel")

- **Journey:** first open, play an album.
- **Expected:** release-grade chrome: track, artist, album, art, controls.
- **What happened:**
  - the header shows a `v0.3.0-m2` milestone badge, although the commits say v1.x (`01-first-open-light.png`);
  - a green `GAPLESS LANE` badge appears in the header once a track plays (`10-after-play.png`);
  - the Now playing card leads with a decode pipeline: "MP3 → mp3 → gapless lane: decoded in full by the browser → Web Audio · gain +3.6 dB (measured) · next joins gapless · trim Lavc tag: 576 samples delay, 960 samples padding; the browser decoder already trimmed it" (`11-now-playing.png`);
  - every header control is a small monospace pill, and Tools, speed, output and visualiser mode are native `<select>` boxes, which reads as a test harness rather than an app.
- **Fix:** hide the version badge (put it in the ? dialog), remove the `GAPLESS LANE` badge, and move the pipeline lines into "Track details" or the Inspector. Replace the Tools `<select>` with a menu button. Use the display font for header buttons.

### M3. The tag editor's cover-art area shows a giant vinyl placeholder over the real cover

- **Journey:** edit a tag.
- **Expected:** a small preview of the current cover, with "Choose image..." and the Save button in view.
- **What happened:** the cover section draws an 809 px wide vinyl-record graphic (the Now playing placeholder art) on top of the real 56 px cover thumbnail and the "Current cover art is kept." text. It pushes "Review and save" below the dialog's fold (`25-tag-editor.png`, `27-tag-written.png`). The write itself worked: the review dialog listed the change and the ID3v2.3 to v2.4 note, and the result read "Written and read back." (`26-tag-review.png`).
- **Cause (observed):** the editor's cover container uses the class `art`, and the global `.art`, `.art:before` and `.art:after` rules (`index.html:81-84`) paint the vinyl.
- **Fix:** rename the editor's class (for example `te-art`) and cap the preview at about 120 px. Add a style-scoping check for class names shared between the shell and the dialogs.

### M4. Two library lists behave differently, and the album page has no Play button

- **Journey:** find and play an album.
- **Expected:** one track list behaviour; an album page with a header and a "Play album" button.
- **What happened:**
  - Library opens on "Tracks": a single click plays, right-click does nothing, and rows have no stars, heart or ⋮ menu (`23-row-context-menu.png`).
  - "Browse" has the albums. There a single click only selects, a selection bar slides in above the list and pushes it down 45 px, and right-click opens a menu (`09-playing.png`, `24-browse-context-menu.png`).
  - The album page shows "Back", the album name and the track rows, with no cover, year, track numbers, total time or Play button (`08-album-open.png`). To play the album I had to select one row, then press Play in the selection bar.
  - In Albums, "Unknown album" sorts first under "Default order" (`07-browse.png`).
- **Fix:** make one list component the only one, with the same click rule everywhere (double-click or Enter plays, single click selects, or the reverse, but one rule). Give the album page a header with cover, year, count, length, and "Play" and "Shuffle" buttons. Sort Unknown album last.

### M5. On a 360 px phone the content area is about 300 px tall

- **Journey:** first open and play, at 360x740.
- **Expected:** a list you can scroll, with compact controls.
- **What happened:** the header wraps to four rows (about 190 px) and the player bar takes about 235 px, so the library shows one track row (`40-mobile-library-light.png`, `43-mobile-library-dark.png`). The volume slider collapses to a dot next to "-10.0 dB". The Now playing title is hidden under the player bar (`41-mobile-now-playing-light.png`). I found no horizontal overflow.
- **Fix:** on narrow screens, put Library, Queue and Now playing in a bottom tab bar and move Sound, AI playlist, Tools, Theme, Mini and ? into one overflow menu. Collapse the player bar to one row (art, title, play, next) that expands on tap. Hide the volume slider on touch devices, where hardware buttons set volume.

### M6. The AI playlist without a model pads the result with unrelated tracks

- **Journey:** ask for an AI playlist without a model.
- **Expected:** the 7 tracks tagged "Ambient" for "calm ambient for a rainy evening", with a note that fewer tracks matched than asked.
- **What happened:** the dialog explains the no-model fallback well. The result then said "Few tracks matched, so the search widened to your most-played tracks. 25 tracks in the preview." It listed the 7 Ambient tracks followed by 18 untagged test-tone files such as `audio-wma` and `audio-dsd` (`33-ai-result.png`). Nothing had been played more than once, so "most-played" is not true here. The "No model here" sentence appears twice.
- **Fix:** return only the matches when the fallback finds fewer than the length, and say "7 tracks match; add more?" with a button that widens the search. Name the real widening source. Show the "No model here" sentence once.

Not fixed, with reasons:

- **Minor 5, Document Picture-in-Picture.** The mini layout is fixed (packed to the top as a card, visualiser included; `minor5-mini-light-after.png`). A PiP window was not built: the shell finds its controls with `document.querySelector`, so moving the player bar into another document would break every control unless the shell is rewritten around element references. That is a larger change than this batch.
- **Minor 11, skin dialog content.** Fixed afterwards by the coordinator once the Webamp patch finished: the dialog now says where classic skins are shared (skins.webamp.org) and the stage accepts a dropped .wsz.
- **Polish 3, keys for Queue and Now playing.** Fixed afterwards by the coordinator: U opens the queue (`view.open`), listed in the keymap. Now playing keeps its existing route (the player bar art and the `now` view).
- **Polish 4, a still for the Milkdrop tile.** The tile text now reads "Milkdrop: choose it to see it". A still image needs a captured frame shipped as an asset, which I did not add.

Engine request (`plan/v1-build/requests-agent-face.md`, item 2): the analysers now read before the volume stage on every route. Every route taps after the node that applies the volume (Reel's gain on R1, the element volume on R2, the R3 gain, the lane volume, then the chain), so a gain of 1/volume between the tap and the analysers undoes it. At volume 0 there is nothing to undo, so the picture is silent. `engine.state().dsp.analyserTap` reports `'pre-volume'`. I checked that Chrome applies the element volume before a `MediaElementAudioSourceNode` (observed ratio 0.100 at volume 0.1). "Link to volume" in the shell now scales the picture once. Tests: `test/audio-engine.test.mjs` (compensation is 4 at volume 0.25, 1 at full volume, 1 when muted).

Tests changed on purpose: `test/library-e2e.html` plays rows with a double click (a single click now selects); `test/ui-smoke.html` gains the full-window and stage gates; `test/audio-engine.test.mjs` finds the analyser through the compensating gain. New: `test/ui-style-scope.test.mjs`.
